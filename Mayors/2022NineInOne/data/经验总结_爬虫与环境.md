## 1. 方法论：复制 → 改常量 → 跑 → 验

新增一个年份的爬虫，最省事的流程就是四步。

### 1.1 直接复制后只改常量

同一年份之间的脚本差异其实只有几个常量，全部集中在档头：

```python
START_URL = "https://vote.nccu.edu.tw/cec/vote3.asp?pass1=..."
OUT_DIR = r"D:\Windows\TaiwanElection\2012Precident\data"
DEFAULT_RAW = os.path.join(OUT_DIR, "2012總統副總統選舉_縣市鄉鎮村里.xlsx")

```

再补上 docstring 年份与 `argparse` 的 description（民国年：2012 → 101 年、2016 → 105 年）。


### 1.2 跑之前先探入口页

不要直接跑完整脚本。先用一小段代码抓 `vote3.asp`，确认：

- 有几位候选人、**姓名与号次**（决定 `DEFAULT_CANDS` 的栏位顺序）
- 该年份的选举届次（写进 docstring，如 2012 是「第 13 任」）
- 表格栏数是否仍是 10 栏（若栏数变了，解析函数也要改）

```python
import requests
from bs4 import BeautifulSoup

url = "https://vote.nccu.edu.tw/cec/vote3.asp?pass1=I:89:I8888888888iii(("
r = requests.get(url, headers={"User-Agent": "Mozilla/5.0"}, timeout=30)
r.encoding = "big5"   # 网站是 big5，不解码会拿到乱码
soup = BeautifulSoup(r.text, "html.parser")
for tr in soup.find("table").find_all("tr"):
    cells = tr.find_all("td", recursive=False)
    vals = [c.get_text(strip=True) for c in cells]
    if len(vals) == 10 and vals[2].isdigit():
        print(vals[1], vals[2], vals[5])   # 姓名 / 号次 / 政党
```

预设候选人顺序要跟网站的号次顺序一致（01→02→03），否则得票率档的栏位顺序会跟使用者预期不同。

### 1.3 跑完必须验证

产出不能只看「有生成档」，要对数字：

| 检查项 | 2012/2016 应有值 |
|---|---|
| 县市级别行数 | 22 县市 |
| 乡镇市区级别行数 | 368 乡镇 |
| 村里层级明细行数 | 7802 村里 |
| 得票率合计 | 每里约 100% |

```python
import openpyxl
wb = openpyxl.load_workbook(path, read_only=True)
for ws in wb.worksheets:
    print(ws.title, ws.max_row, ws.max_column)   # max_row 含表头，记得 -1
```

抽样检查数值型态：得票数应为数字、得票率应为 `43.41%` 这类百分比或两位小数。
若数字对不上官方行政区数，通常是**多抓了总计列**或**漏了某段下钻**，要回头看解析逻辑。

## 2. 改代码时顺手修的坑

### 2.1 直接下标 `xxx_rows[0]` 会崩

原码用 `county_rows[0]`、`town_rows[0]`、`vill_rows[0]` 取「全量键名」。
一旦 0 号候选人那一页抓取失败，`county_rows` 根本没有 key `0`，写档直接 `IndexError`。

改成「取第一组有资料的候选人」：

```python
def first_rows(rows_by_cand):
    """取第一组「有资料」的候选人列，避免 index 0 抓取失败时整档报错。"""
    for i in sorted(rows_by_cand):
        if rows_by_cand[i]:
            return rows_by_cand[i]
    return []

counties = list(OrderedDict.fromkeys(r["county"] for r in first_rows(county_rows)))
```

> 这个修法应该**回灌到 2016 / 2020 版本**，那边有同样的隐患。

### 2.2 得票率档的表头与栏序可能错位

原本：

```python
order = [idx_of[n] for n in cand_names] if all(n in idx_of for n in cand_names) else list(range(len(candidates)))
headers = [...] + [f"{n}得票率" for n in cand_names]   # 用 cand_names
rows rec = ... for i in order                          # 用 order
```

只要有一个候选人名字对不上，`order` 回退成「全部候选人」但 `headers` 还是照 `cand_names` 写，
栏数或名称就会不一致。改成不匹配时连名称一起回退：

```python
idx_of = {c["name"]: i for i, c in enumerate(candidates)}
if all(n in idx_of for n in cand_names):
    order = [idx_of[n] for n in cand_names]
    names = list(cand_names)
else:
    order = list(range(len(candidates)))
    names = [candidates[i]["name"] for i in order]
    print(f"  注意：{cand_names} 與網站候選人不符，改用網站順序 {names}")
```

同时 `rate_lookup` 里的 `vill_rows[i]` 要改成 `vill_rows.get(i, [])`。

### 2.3 弄清两套脚本各产什么，避免互相覆盖

| 脚本 | 产出 |
|---|---|
| `scrape_president_YYYY.py`（主） | ① `..._縣市鄉鎮村里.xlsx`（3 表，得票数+得票率）<br>② `..._得票率.xlsx`（**仅** 各里彙总 1 表） |
| `scrape_president_YYYY_rates.py` | `..._得票率.xlsx`（**3 表**：县市/乡镇/村里纯得票率） |

两者都会写 `..._得票率.xlsx`，**后跑的会覆盖先跑的**。
主脚本其实已经把三个层级的得票率都收进交叉表档了，`_rates.py` 属于冗余；
动手前先确认需要哪一版格式，别让两支脚本互相盖档。

## 3. Windows / PowerShell 5.1 环境踩坑

这台机器的 shell 是 **PowerShell 5.1**，不是 bash。踩过的坑：

### 3.1 没有 bash 的常用指令

- `head`、`tail`、`&&`、`&`（背景执行）**全部不可用**。
- 可用替代：
  - 取前 N 行：`Select-Object -First N`
  - 取后 N 行：`Select-Object -Last N`
  - 串接命令：`cmd1; cmd2` 或 `cmd1; if ($?) { cmd2 }`
- PowerShell 原生参数是 `Get-Content -Tail N`（不是 `tail -N`）。

### 3.2 引号转义是重灾区

`python -c "..."` 外面再包一层 `powershell -Command "..."` 几乎必然炸
（报 `TerminatorExpectedAtEndOfString`、`MissingEndParenthesisInExpression` 等）。

**结论：需要内联 Python 时，写临时 `.py` 档再执行**，不要试图在命令行里转义。
跑正式脚本就直接 `python path\to\script.py`，最干净。

### 3.3 中文输出经 PowerShell 会乱码

PowerShell 5.1 默认以 GBK 解码子进程 stdout，中文全变乱码。

- **判断结果不要看打印文字**，改看：文件是否存在、行数、栏数。
- 需要输出中文时用 `unicode_escape`，保证可读且不受编码影响：

```python
print(name.encode("unicode_escape").decode("ascii"))
# 2012\u7e3d\u7d71\u526f\u7e3d\u7d71\u9078\u8209_\u5f97\u7968\u7387.xlsx
```

### 3.4 后台执行与轮询，别盯 stdout

长时间爬虫不要前台等（会被 tool 超时切断）。正确做法：

```powershell
Start-Process -FilePath 'python3' `
  -ArgumentList 'D:\...\scrape_president_2012.py' `    # 路径没空格就不要加引号
  -RedirectStandardOutput 'D:\...\run.log' `
  -RedirectStandardError  'D:\...\run.err' `
  -WindowStyle Minimized
```

然后**轮询产出**判断进度，而不是读 log：

```powershell
(Get-ChildItem (Join-Path $env:TEMP 'pres2012_cache')).Count   # 已抓页数
Get-ChildItem 'D:\...\data\*.xlsx'                              # 档案是否生成
Get-Process python3 -ErrorAction SilentlyContinue               # 是否还在跑
```

原因：Python 重定向 stdout 是**块缓冲**，日志会长时间是 0 byte，
看起来像卡死，其实只是还没 flush。

⚠️ `Start-Process -ArgumentList` 的引号规则很怪：路径含空格才需要内层引号，
否则反而会把整串粘成错误档名（曾报 `can't open file 'D:\\...\\ D:\\...\\'`）。

## 4. 爬虫本身的有效实践

以下设计值得沿用到其他年份的爬虫：

- **磁碟缓存**（`cache_fetch`）：以 URL 的 SHA1 存 `.html`，断点续跑时直接沿用已抓页面。
  2012 全程约 1158 页，中断后重跑可省下绝大部分时间。
- **三段式下钻**：`vote3.asp`（全国，候选人）→ `vote312.asp`（县市）→ `vote313.asp`（乡镇）→ `vote32.asp`（村里），
  每层的「姓名栏超链接」就是下一层入口。
- **并行抓取**：县市层只有几十页可依序抓；乡镇层（约 22×3 页）与村里层（约 1104 页）
  用 `ThreadPoolExecutor` 并行，`workers=5`、`delay=0.25` 约 3–4 分钟跑完。
- **big5 解码**：`r.encoding = "big5"` 必须手动指定，否则 requests 猜错编码导致解析失败。
