## 二、三層問題逐一剝離（診斷過程）

缺口的成因有**三層**，逐層排查、逐層修復——這次最大的教訓是「第一個修對的 bug 不是真正的根因」：

### 問題 1：`>30m` 長度過濾丟掉大量小段（表層）
- `unary_union` 節點化把縣界裂成 **61343 段**，其中 **46049 個 ≤30m 的小段**（佔總長 29%）被
  「只畫 >30m」的過濾整批丟棄 → 線呈虛線。
- **修法**：全數保留（每個小段都落在真實縣界上），再 `shapely.ops.linemerge`
  把端點相接的段接合成最長線。
- **結果**：虛線大幅改善但**宜蘭／雲林／屏東／臺北仍有嚴重缺段** → 說明還有更深的根因。

### 問題 2：縣市聯集的「內環」被誤當海岸線（**真正的根因**）
- 本島 20 縣市圖資（村里界 dissolve）的聯集內部有 **7251 個內環**——跨縣市的
  圖資細縫（sliver），內環總長 **1403 km**。
- 舊程式 `coast = union.boundary` 把**內環輪廓也當成海岸線**，接著
  `inner = allb.difference(coast.buffer(6.0))` —— 沿細縫的縣市界與內環輪廓**重合
  （距離=0）**，於是被 6m 緩衝**整段誤刪**：3524 km 被刪到只剩 2035 km。
- 這解釋了為什麼缺口呈「斑塊狀」：細縫沿縣界斷續分布，縫隙處整段消失、
  無縫處是實線 —— 正是使用者看到的「很嚴重的缺失」。
- **修法**：海岸線只取聯集各面部件的**外環**：
  ```python
  parts = list(union.geoms) if hasattr(union, "geoms") else [union]
  coast = unary_union([p.exterior for p in parts])   # 只取外環＝真海岸線
  ```
- **驗證數字**：修正後 inner = 3524 km；「allb 有但 inner 沒有」= 1792 km，
  **恰好等於外環總長**（各縣市海岸弧，由 1px 海岸線層負責）→ 陸地邊界零丟失。

### 問題 3：渲染層無關（排除項）
- matplotlib(Agg) 繪線 → 閾值二值化的管線本身可靠；對 1px 參考線的覆蓋檢查
  證明 6px 遮罩對幾何是忠實的。**几何對了，渲染就是對的**。

## 三、最終管線（縣市界／海岸線）

```
counties（25 縣市 dissolve＋清理）
 ├─ thick_cty = 本島 20 縣市
 ├─ union   = unary_union(thick_cty)
 ├─ coast   = unary_union([p.exterior for p in parts])     ← 只取外環（真海岸線）
 ├─ allb    = 各縣市 boundary 的聯集（5315 km，含細縫兩側雙線）
 ├─ inner   = allb.difference(coast.buffer(6m))            ← 3524 km，一段不缺
 ├─ segs    = linemerge(inner pieces)                      ← 接合成連續長線
 ├─ 縣市界 6px：matplotlib 繪 segs → THRESHOLD_VAL 二值化
 └─ 海岸線 1px：draw_layer(coast, 1px) → skimage.thin    ← 金馬同款
```

- 離島（澎湖／金門／連江）外緣仍由 ① 村里層 1px 直繪 → thin，不吃 ② 層。
- 細縫兩側的雙線（各 6px）在縫隙遠窄於 6px 時自然疊合成一條連續粗線。

## 四、驗證方法論（三道關）

1. **向量稽核（`audit_county_segments`）**：每段以中點 30m 內命中的縣市定「兩側縣市」，
   應恰好 2 個；寬縫隙兩側段放寬至 150m 仍 2 縣視為正常。
   實測 **37 組相鄰縣市對全部符合 2008 年行政區**（含思源埡口 2.0km、二仁溪 2.4km 短邊界）；
   剩餘 ⚠️ 皆為三縣交會點 0.0x km 微段（濁水溪口、玉山、秀姑巒山等，真實地理現象）。
2. **光柵覆蓋檢查**：把幾何以 1px Bresenham 直繪當參考線，檢查 6px 遮罩
   （膨脹 1px 後）是否 100% 覆蓋——幾何連續性的量化證據。
3. **分縣市裁剪目視**：按縣市 bbox 從測試圖裁剪放大，逐縣確認無缺口
   （宜蘭／雲林／屏東／臺北四個重災區全部通過）。

測試工具：`python Draw_Taiwan_AtLarge_2008.py --boundaries`
→ 輸出 `全臺灣2008_縣市界海岸線測試圖.png`（僅縣市界 6px＋海岸線 1px，無村里無填色）＋稽核表。

## 五、可復用的經驗教訓（鐵律級）

1. **`union.boundary` ≠ 外輪廓**。多面體聯集的 boundary 含所有內環；
   做海岸線／外輪廓必須逐部件取 `polygon.exterior`。把內環混進「海岸線」，
   後續所有以海岸線為基準的 difference／裁剪都會沿縫隙誤傷真實邊界。
2. **圖資細縫（sliver）是常態**。跨縣市村里圖資 dissolve 後，聯集內部有
   數千個細縫內環（本例 7251 個、1403 km）。任何「扣除海岸帶」的邏輯
   都要先確認海岸線的定義只含真外海。
3. **修對第一個 bug 別急著收工**。30m 過濾是真問題但不是根因；
   修完仍重現 → 換量化手段（向量長度對帳：5315 vs 2035 vs 3524 km）定位下一層。
   **長度對帳**是線稿類 bug 最有效的定位器：總長突然少一截，
   就把「少了的幾何」`allb.difference(inner)` 求出來直接看是什麼。
4. **過濾小段前先問小段是什麼**。節點化產生的 ≤30m 小段都落在真實線上，
   丟掉就是虛線；要防的是「離群的雜線」而不是「短的真線」。
5. **linemerge 是連續化的最後一步**：全數保留＋接合，既連續又不改幾何。
6. **三道關缺一不可**：向量稽核（選擇對不對）→ 光柵覆蓋（連續不連續）→
   分區目視（整體觀感）。只看其中一道會漏。
7. 自檢數字要**與已知地理事實對帳**：37 組相鄰對、三縣交會點座標
   （能高／雪山／卑南主山……）都能對上真實地理，才算「不多選不少選」。
