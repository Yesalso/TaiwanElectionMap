# 總統選舉地圖（tzmm）配樂影片 —— 操作手冊與經驗

> 對象：`dist/final/precident-tzmm/1` 的 8 張看板 PNG + `Video/MP3` 的配樂。
> 工具：`src/tools/make_precident_tzmm_video.py`（本檔描述的這條鏈）。
> 成片：`dist/final/precident-tzmm/總統選舉1996-2024_tzmm_2560x1440_配樂版.mp4`
>
> 撰寫時間：2026-10-20。基於當時的程式碼與目錄實況。

## 0. 這條鏈的樣子

```
  dist/final/precident-tzmm/1/*.png     8 張 2560×1440（1996…2024）
  Video/MP3/*.{mp3,mp4}                 8 段配樂來源（2004 是影片檔，也能當音源）
            │
            ▼
  ┌────────────────────────────────────────────────────────────┐
  │ src/tools/make_precident_tzmm_video.py                     │
  │  畫面：8 張各停留 N 秒，彼此 0.5s 交叉淡化（xfade）          │
  │  聲音：每首只取指定區間，段與段 0.5s 交疊（acrossfade）       │
  │  N ＝ 該段音樂的「結束秒 − 起始秒」                          │
  │  段邊界落在轉場中點 → 音畫鎖死、不累積漂移                   │
  └────────────────────────────────────────────────────────────┘
            │
            ▼
  dist/final/precident-tzmm/總統選舉1996-2024_tzmm_2560x1440_配樂版.mp4
```

與 `README_合成视频.md`（臺北市長鏈）的差別：
那條鏈每場選舉 2 張圖、音樂段可跨年；這條鏈**一年一圖一段樂**，畫面時長直接由音樂區間決定，
且**沒有無聲 intro**（`precident/2` 那支才有「行政區.png」開場）。

## 2. 配樂區間表（`SEGMENTS`）

全部在 `make_precident_tzmm_video.py` 開頭，改這裡就好。
格式：`(標籤, 圖檔名, 配樂檔名, 起始秒, 結束秒)`。

| 年 | 起 → 止 | 段長 | 來源檔（`Video/MP3/`） |
|---|---|---|---|
| 1996 | 0:51 → 1:21 | 30s | 恳丁→基隆(1).mp3 |
| 2000 | 3:05 → 3:43 | 38s | 有你有我-宋楚瑜2000競選總統主題曲…_mp3.mp3 |
| 2004 | 0:43 → 1:18 | 35s | Ray YT｜群星｜台灣有你真好｜歌詞.mp4 |
| 2008 | 1:35 → 2:05 | 30s | 臺灣向前行.mp3 |
| 2012 | 3:04 → 3:32 | 28s | WE ARE ONE.mp3 |
| 2016 | 2:40 → 3:25 | 45s | 《台灣美樂地》為你微笑_南西樂團_mp3.mp3 |
| 2020 | 2:10 → 2:42 | 32s | 2020小英總統競選歌曲《自信勇敢 咱的名》…_mp3.mp3 |
| 2024 | 1:17 → 2:05 | 48s | 「#晴空加長版」…_mp3.mp3 |

合計 286s，扣 7 個 0.5s 交疊 → **成片 282.5s（4 分 42.5 秒）**。

**改區間只要改秒數重跑**（歷次調整：2016 曾 2:40–3:02 → 2:40–3:25；
2024 曾 1:41–2:08 → 1:41–2:06 → 1:17–2:05；1996 曾 0:51–1:05 → 0:51–1:21）。
改完先確認來源檔夠長：`ffmpeg -i 檔案` 看 `Duration` 必須 > 結束秒
（目前最緊的 2000 要 223s、檔案 321.6s；1996 要 81s、檔案 187.1s；都夠）。

## 3. 時間軸怎麼算（別改這個約定）

- 每張圖停留 `dur = 結束秒 − 起始秒`（`durations()`）。
- 第 k 張圖結束處的「轉場中點」＝ `sum(dur[:k]) − k·FADE + FADE/2`（`mid_after(k)`）。
- 音訊段邊界就落在這些中點上，首段從 0 起、末段到片尾止。
- 數學上恆等：**每段實際取到的音樂長度 `lens[i]` 恰好等於 `dur[i]`**，
  所以成片裡每首歌真正播的就是你填的 start→end，不多不少。
- 交疊靠 `acrossfade`（非 `concat`），換曲不爆音；片尾 2.0s 淡出。

## 4. 用法

```bash
PY="C:\Users\Windows\.workbuddy\binaries\python\envs\default\Scripts\python.exe"

"$PY" -X utf8 src/tools/make_precident_tzmm_video.py --level   # 推薦
"$PY" -X utf8 src/tools/make_precident_tzmm_video.py           # 不拉響度
"$PY" -X utf8 src/tools/make_precident_tzmm_video.py --no-music
"$PY" -X utf8 src/tools/make_precident_tzmm_video.py --crf 18 --name 自訂.mp4
```

| 參數 | 預設 | 說明 |
|---|---|---|
| `--out` | `dist/final/precident-tzmm` | 輸出目錄 |
| `--name` | 總統選舉1996-2024_tzmm_2560x1440_配樂版.mp4 | 輸出檔名 |
| `--crf` | 16 | H.264 品質，越小越好、檔案越大（原為 20，已上調） |
| `--preset` | slow | x264 預設；越慢同 crf 畫質越好（veryfast/fast/medium/slow/slower） |
| `--tune` | stillimage | 靜止看板圖專用 tune；要關掉傳 `none` |
| `--level` | — | 逐段 `volumedetect` → 補 `volume` 增益 → `alimiter` 限幅 |
| `--target-mean` | -14.0 | `--level` 目標平均音量（dB） |
| `--no-music` | — | 只出畫面 |

輸出規格：`2560×1440 / 24fps / H.264 High / yuv420p / +faststart`，音訊 `AAC 192k`。
目前成片（282.5s）約 **52 MB**。

**`--level` 實測**（本批 8 段母帶落差 11.7 dB）：

```
1996 -19.7dB → +5.70   2016 -10.4dB → -3.60
2000 -14.0dB → +0.00   2020  -8.0dB → -6.00
2004 -12.5dB → -1.50   2024 -12.7dB → -1.30
2008 -12.7dB → -1.30
2012 -13.6dB → -0.40
```
不加 `--level` 的話 1996 明顯偏小聲、2020 明顯偏大聲，**一定要加**。
（實測值隨「取的區間」而變：1996 段從 14s 加長到 30s 後，實測由 −20.8 變 −19.7 dB，
所以每次改完區間都要重跑，不能抄舊增益。）

## 5. 質檢：這次學到的兩件事

### 5.1 舊方法（波形逐點相減 MAE）不能直接用

`verify_video.py` 的做法是取每段中點 1 秒，跟源 mp3 對應位置逐點相減算相對誤差。
用在這裡會得到 130–160% 的「假錯位」，兩個原因：

1. **`--level` 改了各段增益**，波形振幅對不上（1996 被抬了 +6.8dB，誤差正好 ≈ 145%）。
2. **mp4 裡的 AAC 與源檔有約 −5ms 的固定解碼/編碼延遲**，
   只要錯開幾毫秒，逐點相減就等於拿兩段不相干的波形相減，誤差 ≈ 140%。

### 5.2 改用「互相關」判定，一次看兩個指標

正確的質檢寫法（本次實際使用）：

```
成片取 [段中點−1s, +1s]  → a
源檔取 [期望位置−3s, +8s] → s
在 ±100ms 內逐樣本搜尋，找 cos 相似度最大的偏移 off
輸出：off（應該是個位數 ms、且各段一致）+ 相關係數（應該 > 0.99）
```

實測（2026-10-20 版：1996 改 0:51–1:21、2024 改 1:17–2:05 後）：

```
1996 源  65.0s 成片  15.0s 偏移 -5ms 相關 0.9993
2000 源 203.0s 成片  48.5s 偏移 -5ms 相關 0.9976
2004 源  59.5s 成片  84.5s 偏移 -5ms 相關 0.9954
2008 源 109.0s 成片 116.5s 偏移 -5ms 相關 0.9985
2012 源 197.0s 成片 145.0s 偏移 -5ms 相關 0.9983
2016 源 181.5s 成片 181.0s 偏移 -5ms 相關 0.9991
2020 源 145.0s 成片 219.0s 偏移 -5ms 相關 0.9963
2024 源 100.0s 成片 258.5s 偏移 -5ms 相關 0.9963
Duration: 00:04:42.50  2560x1440 24fps  h264 / aac 48000Hz stereo
```

判定基準：
- **偏移各段一致（−5ms，AAC 固有延遲）→ 無漂移、對位正確**；若某段偏移獨大或正負相反 → 那段填錯了。
- **相關 > 0.99 → 播的就是那首歌的那段**。
- 千萬別用「絕對偏移 ≈ 0」當合格標準，AAC/重採樣一定有個位數 ms 的固定延遲，這是正常的。

質檢腳本用完即刪（臨時檔 `*_tmp.py`），避免污染 `src/tools`。

## 6. 常見坑

| 症狀 | 原因 | 解法 |
|---|---|---|
| 缺圖／缺音樂直接退出 | 腳本開頭會檢查 | 補齊 `precident-tzmm/1/` 或 `Video/MP3/` |
| 某段音樂特別大聲／小聲 | 各源檔母帶落差大（本批 11.7dB） | 加 `--level` |
| 轉場處爆音 | 用 `concat` 硬接 | 已用 `acrossfade`，別改 |
| 某段取不到音樂（ffmpeg 報錯） | 區間超過來源長度 | `ffmpeg -i` 看 Duration，縮短結束秒或換檔 |
| 音樂來源是 `.mp4` | 沒問題 | ffmpeg 直接 `-ss/-t -i xxx.mp4` 只取音軌（2004 就是這樣） |
| 檔名有全形符號／`→`／`#` | Windows + 編碼 | 用 `-X utf8` 跑；檔案走 `os.path.join` 傳參，不要手拼命令列字串 |
| 改了區間卻不確定對不對 | — | 重跑第 5 節的互相關質檢 |
| 畫質被壓縮、文字糊掉 | crf 太大 / preset 太快 | 預設已改 `--crf 16 --preset slow --tune stillimage`；見第 7 節 |

## 7. 畫質：天花板在哪（PSNR 實測）

結論先講：**畫面從頭到尾都是 2560×1440，沒有縮放；差異全部來自 H.264 編碼與 RGB→YUV420p 色彩轉換。**

對 1996 那張 PNG，抽成片同位置的一幀，用 ffmpeg `psnr` 對比原 PNG：

| 編碼設定 | PSNR (avg) | 檔案大小 |
|---|---|---|
| crf 20 + veryfast（舊預設） | — | 22.6 MB |
| **crf 16 + slow + stillimage（現預設）** | **37.93 dB** | **51.7 MB**（282.5s 片長） |
| crf 0（x264 無損）+ limited range | 38.61 dB | 數百 MB 級 |
| crf 0 + full range | 38.94 dB | 更大 |

要點：

1. **crf 16 距離「H.264 無損」只剩 0.7 dB** —— 繼續壓 bitrate 換不回畫質，
   再往下調 crf 只會讓檔案變大、看不出差別。
2. 剩下的 ~4 dB 差距是 **yuv420p 的色度 4:2:0 採樣 + limited range 轉換**造成的，
   這是所有播放器/網頁/微信都支援的格式的固有代價；
   要完全消除只能用 `yuv444p` 或 FFV1 等無損容器，相容性會大幅變差，不建議。
3. 因此**不要把「和 PNG 逐像素一致」當目標**，那是 yuv420p 做不到的事；
   合理目標是「crf 16 視覺上與原圖無差別」，已經達成。

> 一句話：**`SEGMENTS` 的起止秒決定一切（畫面時長＝音樂段長），改表重跑 `--level`，
> 再用互相關看「偏移是否各段一致、相關是否 >0.99」。**
