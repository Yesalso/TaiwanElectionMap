## 日期塊改版 (1)：藍色圓角底版 → 深紅圓盤（依使用者提供的參考樣板）

### 需求
- 使用者給一張參考圖（「2009 / August 30」），要求把看板的日期設計改成那個效果，
  但**仍然使用漢字**（年／月／日 保留，不要改成英文月份）。

### 參考圖量到的比例（圖 198×105，圓盤 x 66–141 / y 10–82）
- 年份數字墨跡高 38.5px、圓盤直徑 76px → **dRatio = 1.95**
- 圓心落在數字墨跡高度的 **70%** 處（cyRatio = 0.70）
- 日期行墨跡高只有年份的 **0.35 倍**，筆畫明顯更細
- 兩行淨空隙 = 0.31 × 年份數字高；**圓盤底緣 ≈ 日期行的基線**
- 圓盤是接近平塗的暗絳紅，實色 RGB ≈ (62,4,17) = `#3e0411`

### 實作
- `js/core/theme.js`：新增 `NT.FONT_NUM_LIGHT`。原因：`FONT_STACK` 第一順位
  「源石黑體 TW H」本身是 heavy、`Noto Sans UI Black` 又只有 900，
  兩個都細不下來 → 把微軟正黑體／蘋方排前面，取 regular/bold 字重。
  （機器實測字型：user fonts 裡有 `NotoSansUI-Black.ttf`、`gensekigothic-h.ttc`、

- `js/core/layout.js` 的 `dateBlock` 整組換掉：拿掉 `w / radius / padX / padY`，
  改成 `disc{ dRatio, cyRatio, inner, outer } + lineGap + year + day`；
  比例全部寫成係數，實際像素由 layers.js 量墨跡算出來。
  year size 96 / cjkSize 32，day size 36 / cjkSize 23。
- `js/render/layers.js`：新增 `measureRich` 量「年份數字自己」的墨跡（`digitM`），
  圓盤直徑與圓心都只看它；`baseY = discCY - cyRatio*digitH + yM.ascent`；
  `boxH` 改為 `= discD`（**注意**：`boxH` 同時餵給市徽高度與左側標題的垂直居中，見下）。

### 派生量（改這個區塊會連帶動到的東西）
`boxH` 132 → 136.5（= 圓盤直徑），因此：
- 市徽高度 132 → 136.5（寬 88.5 → 91.5）

### 驗證（tools/_server.js 8622 + agent-browser）

## 日期塊改版 (2)：圓盤底色換成使用者提供的圓徽圖

### 需求
- 使用者指定：把日期底色改成 `2014NewTaipei/国徽.png`（同日稍早叫 `国旗.png`，已改名）。

### 素材分析
- 原圖 1280×1280 RGBA，**白底**，藍色圓盤（實色 `#000095`）剛好是正方形的**內切圓**，
  中央是白色太陽（12 道光芒）。圓徽圖與同目錄的 `中国国民党.png` 位元組完全相同。
- **不能走 `white_to_alpha.py`**：那條管線是「白 → 透明」，會把**白色太陽一起抽掉**。
  透明範圍是幾何的（內切圓），所以改用圓形遮罩做 alpha、RGB 不動。

### 實作
- `tools/build_assets.py` 新增 `build_emblem()`：
  1. 先把圓外（含圓周內側 2px 殘留抗鋸齒）一律填成 `#000095`，**再**縮圖
     → 否則 LANCZOS 會把白底混進圓的邊緣，深色底上留一圈白暈；
  2. 縮到 512 寬；3. 依半徑做 alpha（邊界 1px 羽化）。
  輸出 `assets/emblem.png`（512×512、36 KB）+ `_preview.png`。
- `write_js()` 多內嵌 `emblem`，`main()` 加入 `build_emblem()`。
  順手修掉 docstring 裡「市徽不做內嵌備援」這句**過時說明**（實作早就有內嵌）。
- `js/slide.js` 新增 `_loadEmblem()`：與市徽同一套規則（http 讀 `disc.src` + 時間戳、
  file:// 用內嵌、都失敗則回 null）。`assets.emblem` = imgs[6]。
- `js/core/layout.js`：`disc.src` / `disc.scrim` / `disc.scrimRadius`。
- `js/render/layers.js`：`boxH` 上面那顆寫死顏色的圓盤改成
  ①先填色畫圓（**為了拿到外陰影**，clip 之後陰影會被裁掉）
  ②clip 成圓 → 畫滿外接正方形（原圖正方形＋內切圓，所以完全貼合）
  ③罩一層暗罩。`scrim` 給 `[offset,color]` 陣列就走 `U.radial`，給字串就平塗。
  讀不到圓徽圖時退回原本的暗絳紅平塗。

### 暗罩的調法（A/B 實測）
- 圓徽很亮、太陽又是白的，而年份是白字 → 不壓暗會糊在一起。
- 平塗 0.46 太弱（太陽 ~140 灰）；中心 0.70 又讓圓徽變成一片糊。
- 最後採**徑向**：`[[0,'rgba(3,7,22,0.62)'],[0.58,'rgba(3,7,22,0.38)'],[1,'rgba(3,7,22,0.12)']]`，
  `scrimRadius = 0.62 × 圓盤直徑`；並把年份黑描邊加厚到 `blur 16 / alpha 0.5 / y 5`。
- 實測：太陽本體 (87,90,98)、圓盤藍底 (1,1,73)、圓盤外緣 (0,2,112)、數字 255 → 對比足夠。

### 驗證
- 圓內藍色像素 4655；**圓外 (R+4 .. R+40) 環帶的藍色像素 = 0**（切圓沒有溢出）。
- 2× 渲染：圓徽鋸齒乾淨、字緣銳利（真重繪非放大）。
- `file://`：`emblemSource / sealSource / mapSource` 全部 `embedded`，
  縮圖是**真的 base64 PNG**、狀態列正常 → 沒有汙染畫布。

- `node --check` 4 個 js、`py_compile` build_assets.py 皆通過。

## 日期塊改版 (3)：日期行字型統一到年份那支

### 需求
- 使用者：「11月29日和2014年的地方字体是一样的」→ 追問後確認方向是
  **把「11月29日」改成和「2014年」同一支字型**（不是要拉開差距）。

### 決定性事實（先量再改）
- 改動前兩行**本來就是不同字型**：年份 `Noto Sans UI Black`(900)、
  日期 `NT.FONT_NUM_LIGHT`(微軟正黑，weight 700 → 落到 `msjhbd.ttc` = Bold)。
- 但兩支都是粗黑體、字寬幾乎相同（0.586em vs 0.596em），
  同尺寸下墨量比 0.66–0.79 → **觀感上就是同一支字**。
  → 所以「統一」這個需求在畫面上其實幾乎看不出變化，重點是把**實作**收乾淨。
- 教訓：使用者說「A 和 B 的字型一樣」時，可能是①在抱怨不該一樣、②在要求改成一樣。
  兩者改法相反，**先問再動**（實測問一次就解決，比改錯再回退便宜）。

### 實作
- `js/core/layout.js`：`dateBlock.day.family` → `NT.FONT_DISPLAY_NUM`、
  `day.weight` 700 → 900（與年份一致）；`cjkWeight` 維持 700（年／月／日 全走 FONT_STACK）。
- `js/render/layers.js`：`dayFamily` 的後備值改 `NT.FONT_DISPLAY_NUM`；註解同步。
- `js/core/theme.js`：**刪掉 `NT.FONT_NUM_LIGHT`**（已無使用者），
  並把它為什麼行不通（源石黑體 H 只有 heavy / 這支只有 900 / 正黑 700 會落 Bold）
  寫進 `FONT_DISPLAY_NUM` 的註解，避免後人再走一次同一條死路。

### 驗證（3× 渲染後逐字量字形）
從 3× 日期塊裁切用行投影切字，比對「同一個數字」在兩行的字形：
| 字 | 年份行 寬高比/墨量比 | 日期行 寬高比/墨量比 | 差 |
|---|---|---|---|
| 1 | 0.587 / 0.5867 | 0.584 / 0.5876 | 0.5% / 0.2% |
| 2 | 0.721 / 0.6276 | 0.718 / 0.6346 | 0.4% / 1.1% |
（改動前同尺寸墨量比差約 34%，現在 ≤1.7% → 同一支字型成立）

- **副作用幾乎為零**：`dayBaseY` 169.25 → 167.25（Noto 數字 ascent 較小，
  基線跟著上移，但墨跡頂點位置不動，視覺位置不變）。
  `boxW` 仍 263.02 → 市徽／標題／投票率位置全部不動。
- 與改動前 1× 輸出 diff：差異像素 **1875**，bbox `x 1246–1392 / y 141–170`
  → 只落在日期行；其餘 9 個區塊（含地圖、兩側候選人、底部票帶）**逐像素 0 差異**。
- `file://` 複驗：字型設定生效、三個素材仍 `embedded`、縮圖仍為真 base64 PNG。
- `node --check` 3 個 js 通過；全域已無 `FONT_NUM_LIGHT` 殘留引用。
