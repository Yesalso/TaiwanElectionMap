### 關鍵技術決定
1. **不用 ES Module**，改用傳統 `<script>` + `NT` 命名空間 → 雙擊 index.html（file://）即可用。
2. **照片以 base64 內嵌在 JS**：file:// 下把本機圖片畫進 canvas 會污染畫布、`toDataURL` 會拋
   SecurityError；內嵌 data URI 則不會，所以匯出 PNG 在 file:// 也正常。
3. **看板用 Canvas 2D 繪製**（非 DOM），`Slide.render(ctx, scale)` 可重複以任意倍率輸出
   → 2× 匯出是真正重繪，不是放大點陣。
4. **去背**：以「逐列背景色模型（左右邊界取樣 + 只在背景連續的列採用）」+ seeded GrabCut +
   「與上/左/右邊界相連的近似背景色區域一律刪除」。候選人照片會有漸層背景，
   單一背景色或 k-means 全都會誤刪頭髮/西裝，逐列模型才穩定。

## 2026-09-29 地圖壓縮改為預乘 alpha 面積平均（消掉白邊與鋸齒）
### 需求
- 使用者回報壓縮後的圖有鋸齒與白邊，要求修正壓縮方式。

### 原因
- 舊做法是「白底 RGB 上 LANCZOS，再用 tol/soft 由白度換算 alpha」，有兩個結構性問題：
  1. 來源是 alpha 只有 0/255 的硬遮罩，縮完 RGB 之後再由白度猜 alpha，邊緣覆蓋率
     算不準 → 過渡帶只有 0.103%（寬 0.26px，幾乎等於階梯，就是鋸齒）。
  2. 透明處的 RGB 是純白，縮圖時白會滲進邊緣像素；`convert(..., unpremultiply=True)`
     再除以很小的 alpha，邊緣顏色誤差中位數 −122（嚴重跑色／墨邊）。
- 原始碼裡 `load_rgb()` 會把 alpha 合成回白底，這一點是關鍵：白底縮放＝白邊。

### 實作（tools/build_vote_map.py）
- `load_rgba()`：來源有真 alpha 就直接用，沒有才退回白底換算（`white_to_alpha`
  現在只當 fallback 與其他素材用）。
- `erase_bands()`：直接在 RGBA 上把標題／圖例區的 alpha 設 0，RGB 不動。
- `trim_transparent()`：依 alpha 裁齊（門檻 >2，避免 1~2 級殘留撐大畫布）。
- `resize_rgba()`：預乘 alpha 空間的面積平均
  1. P = C × A（`ImageChops.multiply`，alpha 要 `.convert("RGB")` 才同 mode）
  2. 整數倍用 `reduce()`（真正的 box 平均）降到 1.4 倍以內
  3. 剩餘倍率用 **BOX** 收尾（不用 LANCZOS：負瓣會在 0/255 硬遮罩邊緣戳出孤立
     針孔與暗點，實測多 9200 個，而且這些雜訊讓 PNG 從 602 KB 脹到 1346 KB）
  4. 反預乘 C = P × 255 / A，A=0 給 0
- `edge_report()`：自檢三項——抗鋸齒帶寬度、邊緣顏色誤差（過渡帶像素還原的顏色
  對照四鄰居中 alpha 最大者）、針孔數。輸出 602 KB 這次順便小了一半。
  過程中修掉自檢本身的 bug：鄰接位移寫成自己對自己（`nb[1:] |= ~mask[1:]`），
  導致 ring 恆為 0 與 `Mean of empty slice` → nan。

### 驗證
- `python tools/build_assets.py` 整包重建通過：vote_map.png 2400×2278、**602 KB**
  （LANCZOS 版 1346 KB）、local-assets.js **855 KB**（原 1893 KB）。
- 自檢：抗鋸齒帶 0.256%（寬 0.7px）· 邊緣顏色誤差中位數 +0.0（平均 +0.1）
  · 針孔 14294 px（＝來源本身 1px 透明縣市界線的基準值，沒有振盪）。
- 掃 18 條海岸線水平線，alpha 過渡都是 `0,0,0,57…227,255,255,255` 單調爬升，
  階梯（只有 0/255）出現 0 次。
- 5 個純色抽樣點與來源 RGB 完全相同（Δ=0,0,0）；alpha bbox 貼齊、四角 alpha=0；
  內嵌副本與 assets/vote_map.png md5 一致；`node --check` 三個 js 檔通過。
- 新舊對照（同一套自檢）：舊法 過渡帶 0.103%/0.26px、顏色誤差中位 −122；
  新法 0.256%/0.7px、中位 +0.0。

## 2026-09-29 修掉 file:// 開啟時整個應用死掉
### 症狀
- 雙擊 `index.html` 以 file:// 開啟：左側投影片清單空白、狀態列停在「就緒」、

## 2026-09-29 游錫堃照片看起來偏左
### 真正的根因（踩了三個坑才找到）
1. **量錯檔案**：`assets/candidate_you.png` 根本沒被使用。候選人照片是 base64
   內嵌在 `data/election-2014.js` 的 `photos` 欄位（`raw.photos[key]` →
   `election-model.js:78` 的 `c.photo` → `slide.js` 的 `U.loadImage(m.left.photo)`）。
   `assets/candidate_*.png` 是同一批照片的另一份檔案副本，容易誤以為是來源。
2. **內嵌版和 assets 版是不同裁切**：zhu 兩邊都 860×1180（同一張），
   但 you 內嵌是 **860×1180**、assets 檔是 **770×1180**（不同圖）。
3. **不是版面 bug**：`drawImageCover` 的水平永遠硬置中（`dx = x + (w - dw)/2`），
