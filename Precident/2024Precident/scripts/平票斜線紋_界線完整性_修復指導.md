# 平票斜線紋「不侵占邊界線」修復指導文檔

> 目的：讓大模型（或其他工程師）把「平票斜線紋不覆蓋邊界線」的修復，套用到**其他年份／其他區域**的同類地圖腳本。
>
> 適用範圍：凡是使用「洪水填充／油漆桶填色」＋「`lines_mask` 邊界線掩碼」＋「`apply_tie_stripes` 平票斜線紋」三段式流程的總統／縣市選舉得票率地圖腳本。
>
> 已驗證範例：`2024Precident/scripts/` 下的 5 個區域腳本（北北基宜、桃竹苗、雲嘉南、高屏、中彰投）與共用模組 `Draw_National_President_2024.py`。驗證結果：北北基宜 5 個平票村里、桃竹苗 2 個平票村里，平票後邊界線 `469280/469280`、`417611/417611` 皆 100% 保持純黑完整。

---

## 一、問題本質

平票圖斑的繪製是把「第 2 名應填的顏色」以 45° 對角斜線紋疊在「第 1 名底色」上。這個疊加若沒有**權威地避開邊界線像素**，斜線紋會畫到（侵占）邊界線上，讓村里界／區界／縣市界出現缺口、斷線或變色。

原代碼的隱患在於：它靠「顏色反推」判斷哪裡是邊界線，例如：

```python
keep_line = arr.any(axis=2)      # 或 not_line = arr.sum(axis=2) > 0
```

這種寫法假設「邊界線像素一定是純黑 (0,0,0)」。一旦邊界線像素因為抗鋸齒、填色溢出、或其他處理變成非純黑，`any/sum` 就會誤判成「可填色區域」，斜線紋就覆蓋上去。

**修復原則**：不要用顏色反推邊界線，改用繪線時就已產生的**權威邊界線掩碼 `lines_mask`**（布林陣列）來排除。

---

## 二、實現路徑（三步）

### 步驟 1：修改 `apply_tie_stripes` 函式簽名，接收 `lines_mask`

在定義 `apply_tie_stripes` 的地方（共用模組或各腳本內），把簽名加上 `lines_mask=None`，並把「非黑判斷」改成「優先用 lines_mask、無則退回純黑反推」：

```python
def apply_tie_stripes(arr, records, w_px, h_px, minx, maxy, sx, sy,
                      lines_mask=None, stripe_px=TIE_STRIPE_PX):
    ...
    tids = rasterize(((g, i + 1) for i, g in enumerate(tie.geometry)),
                     out_shape=(h_px, w_px),
                     transform=Affine(1.0 / sx, 0, minx, 0, -1.0 / sy, maxy),
                     fill=0, dtype="int32", all_touched=False)
    yy, xx = np.indices((h_px, w_px))
    stripe = ((xx + yy) // stripe_px) % 2 == 1

    if lines_mask is not None:
        # 權威界線掩碼：界線像素一律不畫斜線
        fillable = ~np.asarray(lines_mask, dtype=bool)
    else:
        # 退回方案：純黑像素視為界線（arr 為 RGB）
        fillable = arr.any(axis=2)

    m = (tids > 0) & stripe & fillable
    ...
```

**關鍵點**：
- `lines_mask` 必須是與 `arr` 同尺寸 `(h_px, w_px)` 的布林陣列，`True` 表示「這是邊界線像素」。
- `fillable = ~lines_mask` 表示「只要不是邊界線，才允許畫斜線」。
- 保留 `lines_mask=None` 的退回分支，讓沒有 lines_mask 的舊呼叫路徑（如 matplotlib 路徑）仍可運作。

### 步驟 2：讓自檢函式 `full_geom_check` 也接收 `lines_mask`（期望圖同步）

若腳本有逐像素幾何參考自檢 `full_geom_check`，它內部的「平票斜線紋期望圖」也必須用同一套 `~lines_mask` 排除，否則自檢會誤報差異。在期望圖的斜線掩碼加上：

```python
m = (tids > 0) & (((xx + yy) // TIE_STRIPE_PX) % 2 == 1)
if lines_mask is not None:
    m &= ~np.asarray(lines_mask, dtype=bool)
```

並把 `full_geom_check` 簽名加上 `lines_mask=None`。

### 步驟 3：在所有呼叫點傳入 `lines_mask`

找到 `apply_tie_stripes(...)` 與 `full_geom_check(...)` 的呼叫處，加上關鍵字參數：

```python
nat.apply_tie_stripes(arr, records, w_px, h_px, minx, maxy, sx, sy,
                      lines_mask=lines_mask)

_nw, _nout = full_geom_check(arr, records, w_px, h_px, minx, maxy, sx, sy,
                             lines_mask=lines_mask)
```

**前提**：呼叫處的作用域內必須有 `lines_mask` 變數（它通常由村里線層與區/縣市界層合成，例如 `lines_mask = village_skel | town_layer`）。

## 四、如何確認改對了（自檢口徑）

修復後，腳本執行時應看到這一行，且分子分母相等：

```
平票後村里界線：469280/469280 線像素仍為黑（應相等，界線完整）
```

- 分子 = 邊界線像素中仍是純黑的數量
- 分母 = `lines_mask.sum()`（邊界線總像素數）
- 兩者相等 → 邊界線零侵占
- 若分子 < 分母 → 仍有斜線紋覆蓋到邊界線，需回頭檢查 `lines_mask` 是否正確傳入、是否與 `arr` 同尺寸、是否在 `arr[lines_mask] = 0` 之後才呼叫 `apply_tie_stripes`

## 五、套用到「其他年份／區域」時的檢查清單

1. **找函式定義**：`grep -n "def apply_tie_stripes"` 定位該腳本（或它 import 的共用模組）裡的定義。
2. **找呼叫點**：`grep -n "apply_tie_stripes("` 與 `grep -n "full_geom_check("`。
3. **確認 lines_mask 變數名**：不同腳本可能叫 `lines_mask`、`line_mask`、`mask` 等；以實際名稱為準，步驟 3 傳對應變數。
4. **確認呼叫時序**：`apply_tie_stripes` 必須在 `arr[lines_mask] = 0`（把線設黑）之後呼叫，且 `lines_mask` 仍在作用域內、未被 `del`。
5. **無 lines_mask 的舊路徑**（如 matplotlib 直接 `zorder` 分層畫線、沒有掩碼陣列）：只做步驟 1 的退回分支即可，或視情況不引入 lines_mask（保持 `arr.any(axis=2)` 退回邏輯）。
6. **跑一次驗證**：觀察「平票後村里界線：X/Y」是否 X == Y。
7. **語法檢查**：`python -m py_compile 腳本.py`。

## 六、不要做的事（避免再次踩坑）

- **不要**再用 `arr.any(axis=2)` 或 `arr.sum(axis=2) > 0` 作為唯一邊界線判斷——這依賴「純黑」假設，抗鋸齒／深色填色會讓它失效。
- **不要**把 `lines_mask` 的排除邏輯放在「油漆桶單色不變式」自檢之前——斜線紋刻意讓平票區出現兩色，必須在單色自檢之後疊加（保持自檢語義不變）。
- **不要**改動 `stripe` 斜線紋的 45° 網格週期（`(xx+yy)//stripe_px`）與 `tids` 的像素中心規則（`all_touched=False`），那是斜線紋的視覺規格，與邊界線無關。
