# 總統副總統選舉 得票率地圖 —— 跨屆改造標準作業流程（SOP）

> 本文是「把某一屆總統得票率地圖專案複製改造為下一屆」的**可複用指導文件**，
> 已在 **1996→2000→2004→2008** 三次改造中反覆驗證。每次改造照本文步驟執行即可，
> 不必重新摸索。
>
> 各屆專案目錄：`1996Precident/`、`2000Precident/`、`2004Precident/`、`2008Precident/`
> （未來：`2012Precident/`…）。共用模組：`2020Precident/scripts/Draw_National_President_2020.py`（簡稱 `nat`）。

---

## 0. 先讀這一段：判斷「改造複雜度」

改造的複雜度完全取決於**換屆時有幾樣東西會變**。動手前先盤點三件事，避免過度或不足的改動：

| 變項 | 會不會變 | 判斷方法 |
|---|---|---|
| 候選人（人名／人數／政黨） | 每屆必變 | 查中選會當屆登記名單（號次、副手、政黨） |
| 配色（色階 hex） | 視需求 | **是否沿用上一屆，必須先問使用者**；歷屆多次由使用者另行指定色表 |
| 底圖（json／SHP／嘉義市 pre2010） | 多半不變 | 確認「臺中舊市區、嘉義市」等特殊區域是否沿用 |
| 年份／屆次／檔名 | 每屆必變 | 機械替換 |

- **最簡單的情況（如 2004→2008）**：候選人數不變、配色沿用、底圖沿用 → 只需「年份＋人名＋資料」三處替換。
- **較複雜（如 2000→2004）**：候選人 3→2、臺中底圖 SHP→json → 需額外「候選人收斂」「底圖模式切換」。
- **最複雜（如 1996→2000）**：候選人 4→3、明細欄位結構變化 → 需額外「明細得票數欄位依 CAND_NAMES 重挑」。

## 1. 六階段流水線（總綱）

```
① 讀上一屆 README（唯一藍本，避免無關探索）
② 勘驗：資料表結構 + 底圖圖資範圍（寫成 _inspect_*.py，跑一次即丟）
③ 機械替換：年份／屆次／檔名（_convert_year.py，正則守衛）
④ 定向替換：候選人／色階／文案／底圖模式（精確字串配對）
⑤ 校驗：roundtrip 還原比對 + 殘留掃描
⑥ 執行：先跑 1 支代表腳本 → 全跑 6 支 → 四項自檢
```

> 步驟 ②③④⑤ 的一次性工具（`_inspect_*.py`、`_convert*.py`、`_make_rate_xlsx.py`）
> **用畢即刪**，刪前備份到 `.workbuddy/backup/`，避免污染正式 scripts 目錄。

## 2. 各階段詳細做法

### 2.1 讀上一屆 README（①）

- **只讀上一屆的 `scripts/README.md`**，它就是唯一改造藍本；不要做無關探索。
- README 內已累積「與更上一屆的差異」「改造方法論」「執行結果」「待辦」，
  照著它的結構反推本屆要做什麼即可。

### 2.2 勘驗資料表與底圖（②）

寫 `_inspect_data.py`、`_inspect_basemaps.py`，跑一次確認：

- **得票率表**：工作表名（本專案均為「各里彙總」）、欄位名
  （`選舉區別 | 鄉(鎮、市、區)別 | 村里別 | <候選人>得票率...`）。
- **明細表**：工作表名（「村里層級明細」）、候選人得票數欄位
  （形如 `馬英九（02）_得票數`，**號次用全形括號**）。
- **底圖**：`twvillage2012.json` 用小寫 `county/town/village`；
  `twVillage_pre2010.geo.json` 用大寫 `COUNTYNAME/TOWNNAME/VILLAGENAME`。
  **縣市名對不上 → 整區全白**，務必先確認 `COUNTY_ALIAS`（如臺北縣→新北市、臺南縣→臺南市）。

### 2.3 機械替換年份／屆次／檔名（③）

寫 `_convert_year.py`，核心是三件事：

```python
# 1) 正則守衛：只替換「獨立數字」，避免誤傷 20000 / 12000 / 2004.0 等常量
RE_2004 = re.compile(r"(?<!\d)2004(?!\d)(?!\.0)")

# 2) 屆次：第十一屆 → 第十二屆（注意先長後短，避免「第十一屆」被「第十屆」規則誤傷）
txt = txt.replace("第十一屆", "第十二屆")
txt = txt.replace("第十屆", "第十一屆")   # 僅當上一屆 README 也提到更早屆次時才需要

# 3) 檔名：_2004.py → _2008.py；同時 os.remove 舊檔
```

**替換順序陷阱**：若同時要「2004→2008」和「2000→2004」，務必**先大後小**（先 2004 後 2000），
否則 `2004` 會被先替換成 `2008`、再被 `2008→?` 規則二次誤傷。

### 2.4 定向替換候選人／配色／文案（④）

候選人、色階是**多行結構**（`CAND_NAMES`、`RATE_COLOR_STOPS`、docstring 表頭），
**不要用正則**，用「完整舊字串 → 新字串」的 `str.replace` 最安全。

**候選人一對一換名**（2004→2008 實例）：

```python
REPL = {
    '連戰': '馬英九',
    '陳水扁': '謝長廷',
    '宋楚瑜': '蕭萬長',   # 副手也要換
    '呂秀蓮': '蘇貞昌',
}
```

**換名時務必同時核對三件事**（若對不上就是資料或號次搞反了）：

| 欄位 | 2004 | 2008 | 是否需改 |
|---|---|---|---|
| `CAND_NAMES` 順序 | 連戰、陳水扁 | 馬英九、謝長廷 | 換名 |
| 號次 | 陳01／連02 | 謝01／馬02 | **若政黨對應不變則免改** |
| 政黨 | 藍／綠 | 藍／綠 | 免改 |
| 色階 | 藍 `#A6E9FF→#010D29`、綠 `#E8FFE0→#071A09` | 同 | 沿用（先問使用者） |

> **2004→2008 的幸運點**：號次恰好「01=民進黨、02=國民黨」與 2004 相同，
> 故副手、政黨、號次全部一一對應，只需換人名，零額外改動。若未來某屆號次政黨反了，
> 就要同步對調 `RATE_COLOR_STOPS` 兩組順序。

### 2.5 生成器與 6 支產出腳本「雙寫」同步（④ 重點）

- `_gen_*.py` 內建 **HEADER 模板**（含 `CAND_NAMES`／色階／docstring），
  而 6 支產出腳本各自**再帶一份相同 header**。
- **改候選人／色階／文案時，生成器模板與現有 6 支腳本都要改**，
  否則重生成會產生 diff，或某支腳本漏改。
- 改完後**重跑生成器**，用 `md5` 或 `diff` 比對「生成器重寫的三支（TCM4/TCN3/TaichungCity）」
  與「手動替換後的版本」是否**逐字元相同**，作為一致性驗收。
- YCT4（嘉義市 pre2010）、South2（那瑪夏更名）含手工增補邏輯，**生成器無法復現**，
  不重生成、不覆蓋。

### 2.6 校驗：roundtrip 還原 + 殘留掃描（⑤）

```python
def invert(txt):  # 還原比對：新檔 → 舊檔 應逐字元相同
    txt = txt.replace("第十二屆", "第十一屆")
    txt = RE_2008.sub("2004", txt)
    return txt
```

- roundtrip 不一致 = 機械替換誤傷（例如把「2008 三村復舊名」這種無關文字也改了，要用哨兵避開）。
- 殘留掃描：替換後 grep 舊候選人名（`連戰`、`陳水扁`…）確認歸零。
- 檔案務必 `encoding="utf-8"`，讀寫保持原換行（CRLF/LF 別弄亂）。

### 2.7 執行與四項自檢（⑥）

1. **先跑 1 支代表腳本**（建議含特殊機制的 YCT4 或 TCM4），四項自檢全綠再全跑。
2. **全跑 6 支**：North4 / TCM4 / YCT4 / South2 / TCN3 / TaichungCity。
3. **四項自檢＝驗收門檻**：
   - 油漆桶不變式：非單色區域 **0**
   - 非允許色像素 **0**
   - 村外非白像素 **0**
   - 幾何參考差異 **≤0.0051%**

> Windows 上長時間腳本偶發 `pil_img.save` 的 `OSError Errno 22`（檔案被占用），
> 單獨重跑該支即可，非邏輯錯誤。

## 3. 資料前置：得票率 xlsx 若缺，由明細表轉出

若 `data/<年>總統副總統選舉_得票率.xlsx`（工作表「各里彙總」）不存在、
但已有爬蟲產出的 `<年>總統副總統選舉_縣市鄉鎮村里.xlsx`（工作表「村里層級明細」），
寫 `_make_rate_xlsx.py` 轉換，**無需重新爬網**：

```python
CAND_NAMES = ["馬英九", "謝長廷"]   # 順序＝ RATE_COLOR_STOPS 順序
# 依 CAND_NAMES 逐一挑得票率欄（欄名形如「謝長廷（01）_得票率」）
rate_cols = {n: next(c for c in dc.columns
                     if c.endswith("_得票率") and c.startswith(n)) for n in CAND_NAMES}
# 輸出欄位：選舉區別 | 鄉(鎮、市、區)別 | 村里別 | <候選人>得票率...
# 得票率 float：去掉 %、四捨五入兩位小數
```

## 4. 候選人數變化時的連鎖清單（3→2 或 2→3 時才需要）

`CAND_NAMES` 人數改變時，務必同步以下**全部**，漏一處即出錯：

1. `CAND_NAMES`（新增/刪除候選人）
2. `CAND_RATE_COLS = [f"{n}得票率" for n in CAND_NAMES]`（自動，但確認）
3. `RATE_COLOR_STOPS`（對應組數增刪）
4. docstring 表頭與色階說明文案
5. 報告文案（「三強」↔「兩強」）
6. **明細得票數欄位挑選**：必須 `依 CAND_NAMES 逐名挑選`，不可「取全部 `_得票數` 欄」，
   否則多出來的候選人得票數會汙染跨里合併的加總：
   ```python
   cnt_cols = [next(c for c in dc.columns if c.endswith("_得票數") and c.startswith(n))
               for n in CAND_NAMES]
   ```

## 5. 底圖來源切換的三類做法

| 情境 | 做法 |
|---|---|
| 全區改用同名 json | `REGIONS` 裡 `base="json"`（一行） |
| 只換某縣市村里層（嘉義市） | 保留 `CITY_GEOJSON` + `_apply_city_pre2010` 機制，**不動** |
| 從大範圍 json 取子集另畫一圖（臺中舊市區） | 新增 `json_oldcity` 模式 + `TARGET_TOWNS` 篩選 |

```python
TARGET_TOWNS = ['中區','東區','西區','南區','北區','西屯區','南屯區','北屯區']
gdf = gdf[gdf["TOWNNAME"].astype(str).str.strip().isin(TARGET_TOWNS)].copy()
```

## 8. 已知陷阱速查表

| 陷阱 | 症狀 | 解法 |
|---|---|---|
| 年份誤傷 | `20000`、`12000`、`2004.0` 被改 | 正則守衛 `(?<!\d)2004(?!\d)(?!\.0)` |
| 替換順序錯 | 「先小後大」二次誤傷 | 先 2004→2008 再 2000→2004 |
| 生成器漏改 | 重生成產生 diff | 模板 + 6 支腳本雙寫同步 |
| 縣市名對不上 | 整區全白 | 先勘驗 `COUNTY_ALIAS` |
| 嘉義市／那瑪夏被生成器覆蓋 | 手工邏輯遺失 | 生成器 `WRITE_CODES` 只含 TCM4/TCN3/TaichungCity |
| 明細欄位取錯 | 跨里合併加總被汙染 | 依 `CAND_NAMES` 逐名挑選 |
| 號次政黨反了 | 藍綠填反 | 核對號次，必要時對調色階兩組 |
| 無資料留白暴增 | 新屆村里集合 vs 2012 圖資差異 | 記錄於 MD 第 1 節，必要時補沿革合併表 |
| 存檔瞬時 OSError | 檔案被占用 | 單獨重跑該支 |
